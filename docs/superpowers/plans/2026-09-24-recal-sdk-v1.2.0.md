- [ ] **Step 3: Derive the ids locally**

In `apps/api/src/router/extern/index.ts`, above `export const externalRoute`:

```ts
const toPascalCase = (segment: string): string =>
	segment
		.split(/[\W_]+/)
		.filter(Boolean)
		.map((word) => word.charAt(0).toUpperCase() + word.slice(1))
		.join('')

/**
 * Derives an operation id from a route, reproducing hono-openapi 1.3.3's scheme.
 *
 * These ids are the public SDK's symbol names — `recal-sdk` generates one function and
 * one type per operation from them. Left to the library they are a dependency's
 * implementation detail, and the 1.1 → 1.3 bump renamed all 33 parameterised operations
 * at once. Deriving them here makes them Recal's contract, so a future bump cannot move
 * them; `openapiContract.test.ts` holds the values.
 */
const operationId = (route: RouterRoute): string =>
	route.path === '/'
		? `${route.method.toLowerCase()}Index`
		: route.path
				.split('/')
				.reduce(
					(id, segment) =>
						segment.startsWith(':')
							? `${id}By${toPascalCase(segment.slice(1).replace(/\{.*$/, ''))}`
							: id + toPascalCase(segment),
					route.method.toLowerCase(),
				)
```

Add `import type { RouterRoute } from 'hono/types'` to the imports, and one more key to the `openAPIRouteHandler` options object:

```ts
		defaultOptions: { ALL: { operationId } },
```

- [ ] **Step 3: Add `unwrapEnvelope`**

In `src/utils/response.ts`, after `unwrapResponse`:

```ts
/**
 * Unwraps a HeyAPI response to the API's whole envelope rather than its `data` field.
 *
 * For the responses that carry a sibling of `data` — the organization free/busy routes
 * report `failedUsers` there — where dropping it would let a partial answer read as a
 * complete one. Error handling is identical to {@link unwrapResponse}.
 */
export function unwrapEnvelope<T>(response: HeyApiResponse<unknown>): T {
    if (response.error && typeof response.error === 'object' && Object.keys(response.error).length > 0) {
        return unwrapResponse(response as HeyApiResponse<T>)
    }

    if (!response.data) {
        throw new RecalError('No data in response', response.response?.status, response)
    }

    return response.data as T
}
```

## ⚠️ v1.2.0 — Partial organization answers are now visible (2026-09-24)

### ✨ Added
- **`organizations.getBusyTimes()` and `organizations.getScheduling()` report `failedUsers`.**
  The API answers 200 with the users whose calendars it could not read, rather than failing
  the whole request. Each entry carries the user's `customId` and a reason. A non-empty
  `failedUsers` means the busy times or slots beside it are a *partial* answer.
- `FailedFreeBusyUser` is exported from the package root.
- `403` and `429` are documented on the user free/busy and scheduling endpoints, and the
  user free/busy routes document a `400` for requesting more calendars than the limit allows.

### ⚠️ Upgrading
Two breaking changes, both mechanical.

**1. The two organization methods return an envelope.** They resolved to the payload;
they now resolve to `{ data, failedUsers }`.

```typescript
// before
const busy = await recal.organizations.getBusyTimes('acme', { start, end })
busy.forEach(…)

// after
const { data: busy, failedUsers } = await recal.organizations.getBusyTimes('acme', { start, end })
if (failedUsers.length > 0) { /* the busy times below are partial */ }
busy.forEach(…)
```

No other method changed shape.

**2. Generated type exports were renamed.** A path parameter now contributes `By<Param>`,
so `GetV1UsersUserIdSchedulingData` is now `GetV1UsersByUserIdSchedulingData`, and likewise
for all 33 parameterised operations. This affects only the generated `GetV1…` / `PostV1…` /
`PutV1…` / `DeleteV1…` names; the domain types (`Calendar`, `Event`, `User`, `TimeRange`,
`Provider`, …) are untouched, and no method name, argument, or URL changed. The operation
ids these names derive from are now pinned in the API, so they will not move again.
```
